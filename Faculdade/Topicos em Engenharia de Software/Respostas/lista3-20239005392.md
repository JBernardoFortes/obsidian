## 1. Processo de Comunicação

A definição de um código ou protocolo comum é fundamental para que o emissor e o receptor consigam trocar informações e interpretá-las corretamente. Sem regras compartilhadas, os dados podem ser enviados, mas não compreendidos. Os protocolos estabelecem regras para a transmissão, o formato das mensagens, a sincronização e o tratamento de erros, garantindo uma comunicação eficiente e confiável.

## 2. Modelos de Camadas

O modelo OSI possui sete camadas: Física, Enlace, Rede, Transporte, Sessão, Apresentação e Aplicação. Já o modelo TCP/IP geralmente é representado por quatro camadas: Acesso à Rede, Internet, Transporte e Aplicação.

A principal vantagem da arquitetura em camadas é a modularidade. Cada camada possui funções específicas e pode ser desenvolvida ou modificada sem exigir mudanças em toda a arquitetura, desde que suas interfaces e regras de comunicação sejam respeitadas. Isso facilita a manutenção, a interoperabilidade e a identificação de problemas.

## 3. Interação entre Camadas

Ao acessar uma página web, os dados passam pelas camadas do modelo TCP/IP no dispositivo cliente. Na camada de Aplicação, o navegador utiliza protocolos como HTTP ou HTTPS. Na camada de Transporte, o TCP segmenta os dados e fornece mecanismos de confiabilidade, enquanto o UDP pode ser utilizado com protocolos como QUIC. Na camada Internet, o IP define os endereços de origem e destino dos pacotes. Por fim, a camada de Acesso à Rede prepara os dados para a transmissão pelo meio físico.

No servidor, o processo ocorre inversamente: os dados são recebidos e processados pelas camadas inferiores até chegarem à camada de Aplicação, onde o servidor web interpreta a requisição e envia a resposta.

## 4. Máscara de Rede

A máscara de rede determina qual parte de um endereço IPv4 identifica a rede e qual parte identifica o dispositivo (host). Ela permite que os dispositivos identifiquem se um endereço de destino pertence à mesma sub-rede ou se a comunicação precisa passar por um roteador.

Se dois hosts utilizarem máscaras incompatíveis, poderão interpretar de maneira diferente os limites da sub-rede. Um dispositivo pode considerar o outro como local, enquanto o outro pode considerar que o destino está em uma rede remota. Isso pode causar falhas de comunicação devido ao envio incorreto dos pacotes ou à ausência de um roteador configurado adequadamente.

## 5. IP Público e Privado

O esgotamento dos endereços IPv4 públicos ocorre porque o espaço de endereçamento IPv4 possui aproximadamente 4,3 bilhões de endereços possíveis, muitos dos quais não estão disponíveis para uso público. A expansão da Internet aumentou a demanda por esses endereços.

Os endereços IP privados permitem que diversos dispositivos utilizem endereços em redes locais sem precisar de um IP público exclusivo para cada um. Como esses endereços não são roteados diretamente pela Internet pública, diferentes redes podem reutilizar as mesmas faixas privadas. Com o auxílio do NAT, vários dispositivos podem compartilhar um único IP público, reduzindo a demanda global por endereços IPv4 públicos.

## 6. NAT (Network Address Translation)

O NAT é uma função do roteador que traduz endereços IP privados em um endereço IP público ao encaminhar pacotes para a Internet. No retorno, o roteador utiliza uma tabela de traduções para encaminhar as respostas aos dispositivos corretos.

Para permitir que vários dispositivos compartilhem simultaneamente um único IP público, geralmente é utilizado o PAT (Port Address Translation). Essa técnica diferencia as conexões por meio dos números das portas de origem, associando cada conexão à respectiva máquina da rede local.

Assim, diversos dispositivos podem acessar serviços na Internet sem precisar de um endereço IPv4 público individual, contribuindo para a economia de endereços disponíveis.

## 7. Conectividade

Se um computador consegue se comunicar com outros dispositivos da rede local, mas não consegue acessar a Internet, algumas causas possíveis são:

- Máscara de rede incorreta: o computador pode interpretar incorretamente quais endereços pertencem à rede local.
    
- Gateway padrão ausente ou incorreto: sem um gateway válido, o computador não consegue encaminhar pacotes destinados a outras redes.
    
- Endereço IP incorreto: uma configuração inadequada pode impedir a comunicação com redes externas.
    
- Conflito de endereços IP: dois dispositivos podem estar utilizando o mesmo endereço, causando problemas de conectividade.
    
- Falha no roteador ou no NAT: o roteador pode estar sem acesso à Internet ou não estar realizando corretamente a tradução dos endereços privados.
    
- Problemas de DNS: o computador pode ter conectividade IP com a Internet, mas não conseguir traduzir nomes de domínio, como `google.com`, em endereços IP.
