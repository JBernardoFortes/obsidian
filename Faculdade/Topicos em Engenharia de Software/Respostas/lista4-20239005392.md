## 1. Arquitetura de VPC e CIDR

O planejamento dos blocos CIDR é importante para definir a faixa de endereços IP disponíveis dentro de uma VPC. Um planejamento adequado evita conflitos de endereços entre redes, facilita a comunicação com outras VPCs e redes locais e permite dividir a infraestrutura em sub-redes de acordo com suas necessidades. Além disso, garante que haja endereços suficientes para as instâncias e outros recursos.

## 2. Sub-redes Públicas vs. Privadas

A diferença fundamental está na tabela de rotas associada à sub-rede. Uma sub-rede pública possui uma rota para um Internet Gateway (IGW), permitindo a comunicação com a internet. Já uma sub-rede privada não possui uma rota direta para o IGW. Ela pode utilizar um NAT Gateway para permitir que seus recursos acessem serviços externos sem receber conexões iniciadas diretamente pela internet.

## 3. Internet Gateway (IGW)

O Internet Gateway permite a comunicação entre os recursos de uma VPC e a internet, realizando a função de conexão entre a rede virtual e a rede externa. Para funcionar, ele precisa estar associado à VPC e ser referenciado na tabela de rotas.

Uma instância não consegue acessar a internet apenas por possuir um IP público, pois o IP não estabelece sozinho o caminho para o tráfego. É necessário que exista um IGW e uma rota adequada, além de regras de segurança que permitam a comunicação.

## 4. Tabelas de Rotas

As tabelas de rotas determinam para onde os pacotes de dados devem ser encaminhados dentro de uma VPC. Cada rota possui um destino, definido por um bloco CIDR, e um alvo, como uma rede local da VPC, um Internet Gateway ou um NAT Gateway. Dessa forma, elas controlam o encaminhamento do tráfego entre sub-redes e redes externas.

## 5. Alta Disponibilidade (Zonas de Disponibilidade)

Distribuir sub-redes em diferentes Zonas de Disponibilidade (AZs) aumenta a disponibilidade e a tolerância a falhas, pois as zonas possuem infraestrutura independente. Se uma zona apresentar uma falha, os recursos implantados em outra zona poderão continuar funcionando.

Por exemplo, um site pode ter servidores em duas AZs diferentes, com um balanceador de carga distribuindo as requisições. Se uma zona ficar indisponível, o tráfego poderá ser direcionado para os servidores da outra zona, mantendo o serviço acessível.

## 6. Grupos de Segurança

Os Security Groups são firewalls virtuais associados a instâncias e outros recursos compatíveis da AWS. Eles controlam o tráfego de entrada e saída por meio de regras que especificam protocolos, portas e origens ou destinos permitidos. São stateful, ou seja, permitem automaticamente o tráfego de resposta a uma conexão autorizada.

Exemplo: em um servidor web, pode-se permitir tráfego de entrada nas portas TCP 80 (HTTP) e 443 (HTTPS) para qualquer endereço IP, enquanto a porta TCP 22 (SSH) fica restrita ao IP do administrador.

## 7. Protocolo NAT (NAT Gateway)

O NAT Gateway é necessário quando instâncias em sub-redes privadas precisam iniciar conexões com a internet, por exemplo, para baixar atualizações ou instalar pacotes, sem ficarem diretamente acessíveis por conexões iniciadas pela internet.

Ele permite que essas instâncias utilizem um endereço IP público para acessar serviços externos, enquanto as conexões de entrada não solicitadas não são encaminhadas automaticamente para elas. Para funcionar, a tabela de rotas da sub-rede privada deve direcionar o tráfego externo ao NAT Gateway.

## 8. Serviço de DNS na VPC

A opção DNS Resolution permite que os recursos da VPC utilizem o serviço de resolução de nomes DNS fornecido pela AWS. Se ela for desativada, as instâncias poderão ter dificuldades para resolver nomes de domínio em endereços IP.

A opção DNS Hostnames controla a atribuição de nomes DNS públicos ou privados aos recursos, conforme o tipo de endereço e a configuração da VPC. Se for desativada, recursos que dependem desses nomes poderão não receber ou utilizar corretamente os nomes DNS esperados. Isso pode dificultar a comunicação por nomes de domínio e exigir o uso direto de endereços IP.

## 9. Serviço DHCP

O DHCP Option Set permite configurar informações de rede que são fornecidas automaticamente às instâncias da VPC por meio do DHCP. Entre essas informações estão o nome de domínio, os servidores DNS, o nome NetBIOS e os servidores NTP, conforme as opções configuradas.

Essas informações ajudam as instâncias EC2 a configurar sua comunicação de rede durante a inicialização, sem que seja necessário definir manualmente cada parâmetro. A AWS também fornece configurações DHCP padrão para as VPCs.

## 10. Cenário de Integração

Quando o servidor web precisa acessar o banco de dados, o pacote sai da instância web e segue conforme a tabela de rotas da sub-rede pública. Como o destino é um endereço IP privado pertencente à mesma VPC, o tráfego é encaminhado internamente pela infraestrutura de rede da AWS até a sub-rede privada do banco de dados.

Ao chegar ao banco de dados, o Security Group associado a ele verifica se a conexão de entrada é permitida. Por exemplo, pode autorizar conexões na porta TCP 5432, utilizada pelo PostgreSQL, somente a partir do Security Group do servidor web.

Se as regras permitirem, o banco de dados recebe a conexão e envia a resposta pelo caminho de retorno. Como os Security Groups são stateful, o tráfego de resposta a uma conexão autorizada é permitido automaticamente. Assim, o banco permanece protegido contra conexões diretas não autorizadas, enquanto o servidor web consegue acessá-lo.
